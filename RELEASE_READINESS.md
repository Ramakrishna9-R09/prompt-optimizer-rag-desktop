# Prompt Optimizer Release Notes

## Product Modes

- `Ctrl+Shift+Space`: No-memory LLM mode. Reads only the current active textbox, rewrites it into a stronger prompt, and pastes the result back.
- `Ctrl+Alt+Space`: Prompt Autopilot with workspace-isolated advanced memory RAG. Captures current-window chat text and application/workspace identity; routes intent; runs adaptive HyDE expansion, hybrid retrieval, RRF reranking, CRAG-style relevance grading, and spotlighting; generates multiple candidates; validates and ranks them; then learns from the accepted result and pastes the best candidate back. The original single-result RAG mode remains available when Autopilot is disabled.
- `Ctrl+Alt+F10`: Global pause/resume switch. It remains registered while optimization is paused and while the application window is hidden. Pausing releases the two action shortcuts; resuming registers them again and persists the state.

## Local RAG Architecture

- Memory is stored locally at `%USERPROFILE%\.prompt-optimizer\memory-index.json`.
- Current-window chat text is captured with Windows UI Automation when available.
- Configuration schema 3 stores the last detected application/workspace, explicit workspace-to-project bindings, and the project context policy.
- `Match Active Workspace` is the default. An unrelated selected repository is never used as an automatic fallback; pinned project mode and workspace bindings are explicit choices.
- Memory, history, retrieval, and caches are isolated by application/workspace. Legacy unscoped memory is excluded from scoped runs, and cross-workspace reuse is disabled by default.
- Retrieved memory combines BM25 and local feature-vector similarity, then applies RRF, reranking, deduplication, and relevance grading.
- Secrets are redacted before indexing or sending context.
- Memory can be disabled, auto-learning can be disabled, and the index can be cleared from Settings.

See `ADVANCED_RAG_ARCHITECTURE.md` for the exact runtime stages and the mapping from the supplied enterprise diagram to this desktop implementation.

## Prompt Autopilot 1.1

- Produces two to four strategy-diverse candidates in one model request.
- Applies local validation, redaction, deduplication, quality scoring, and ranking.
- Runs at most one repair request when every candidate misses the configured quality gate.
- Uses expiring main-process sessions so the renderer can accept only candidates generated by the application.
- Supports explicit handoff to Codex, VS Code, Cursor, Claude, Antigravity, and OpenCode. Automatic IDE handoff is disabled by default.
- Tracks a local activation funnel without storing prompts or uploading analytics.

## Commercial Validation Model

The product configuration contains a testable $1M ARR planning scenario:

- 2,500 Pro subscribers at $24/month = $720,000 ARR.
- 500 Team seats at $49/month = $294,000 ARR.
- Projected total = $1,014,000 ARR.

This is a pricing and adoption target, not booked revenue. Production validation must measure activation (first accepted suggestion), suggestion acceptance, weekly active days, context-mode use, IDE handoffs, paid conversion, retention, churn, support load, and model cost per active user. The application now supplies the local product counters needed for early validation; real revenue and retention require deployed billing and customer data.
